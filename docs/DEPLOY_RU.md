# Выкладка

Перед выкладкой в основной папке проекта:

```powershell
npm ci
npm run check
```

Сборка Cloudflare складывается в `dist/server` и `dist/client`; эти каталоги
создаёт сборщик, руками их трогать не нужно. Конфигурация воркера для выката —
`dist/server/wrangler.json`.

## Публикация на Cloudflare

Приложение — воркер Cloudflare: `worker/index.ts` отдаёт страницы, `dist/client`
уходит статикой, база D1 подключается привязкой `DB`. Другой хостинг потребовал
бы переписывать серверную часть.

Шаги выполняются один раз, владельцем аккаунта Cloudflare.

**1. Вход.** Откроется браузер, доступ подтверждается там:

```
npx wrangler login
```

**2. База.** Создаётся пустая база и печатается её идентификатор:

```
npx wrangler d1 create aedexa
```

Полученный `database_id` вписать в `wrangler.jsonc` вместо заглушки, после чего
накатить схему из `migrations/`:

```
npm run db:remote
```

**3. Публикация.** Собирает проект и выкладывает воркер:

```
npm run deploy
```

Адрес вида `aedexa.<поддомен>.workers.dev` печатается в конце. На нём сайт уже
работает: посадка, топосъёмка, архив и экспорт считаются в браузере и серверных
ключей не требуют.

**4. Свой домен** — `aedexa.site`, зарегистрирован в Namecheap.

1. В панели Cloudflare: **Add a site** → `aedexa.site` → план Free.
2. Cloudflare покажет два адреса вида `имя.ns.cloudflare.com`.
3. В Namecheap: **Domain List → Manage → Nameservers → Custom DNS** — вписать
   оба вместо `dns1.registrar-servers.com` и `dns2.registrar-servers.com`.
4. Дождаться в панели Cloudflare состояния **Active** (от получаса до суток).
5. В `wrangler.jsonc` в `routes` указан домен — поставьте свой и повторите
   `npm run deploy`.

Запись DNS и сертификат Cloudflare выпустит сам. Пока домен не переехал, выкат с
`routes` падает с «zone not found»: нужно дождаться переезда.

**5. Ключ модели.** Нужен только режиму 2D → 3D. Без ключа режим не показывается
и ничего не ломает. Ключ кладётся в секреты воркера, а не в `.env`:

```bash
npx wrangler secret put FEATHERLESS_API_KEY
```

После смены секретов воркер перезапускается сам.

## Окружение и ограничения

- Node.js не ниже версии, указанной в `package.json`; зависимости фиксируются lock-файлом.
- Без AI-ключей доступны локальные CAD/посадка/архив; реконструкция через провайдера требует серверных настроек из `.env.example`.
- Ключи вводятся отдельно в секреты целевого окружения; клиентские переменные `VITE_*` для ключей не используются.
- Архив объектов хранится в браузере пользователя, учётные записи и проекты — в D1.
- В тестах ответы модели подменены, поэтому работу с настоящим Featherless и открытие экспортов в CAD-программах проверяйте вручную.
- DXF читается в модуле посадки; текущий WASM-парсер реконструкции читает DWG. Для 2D → 3D из DXF нужен экспорт в DWG или изображение. PDF модель не принимает: нужны PNG или JPEG страниц.
- Разбор подписей и групп крупной топосъёмки моделью занимает минуты: на чертеже с сотней подписей — около десяти.

`npm run deploy` сразу публикует сайт.

Если Windows блокирует обновление пакетов (`EBUSY`), сначала остановите dev-сервер этого проекта. Если корпоративный корневой сертификат уже установлен в Windows, Node можно запустить с `--use-system-ca`; отключать проверку TLS не требуется.
