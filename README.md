# AEDEXA

Устройство описано в [архитектуре](docs/ARCHITECTURE_RU.md), выкладка — в
[инструкции](docs/DEPLOY_RU.md).

Браузерная платформа ранней стадии проектирования: чертёж участка превращается
в проверяемую модель — граница, охранные зоны сетей, пятно застройки, рельеф в
объёме и постройки с проверкой отступов. Всё считается на устройстве пользователя;
сервер используется для реконструкции 2D → 3D и запрашиваемого пользователем ИИ-анализа подписей и групп CAD.

Главный принцип: у каждой цифры есть происхождение. Любой вывод несёт статус —
`PASS`, `FAIL`, `MISSING_DATA` или `EXPERT_REVIEW` — и ссылку на правило, по
которому он получен. Если данных в чертеже нет, платформа говорит об этом прямо,
а не подставляет типовое значение.

## Режимы

| Режим | Что делает |
|---|---|
| **Посадка и отступы** | DWG, DXF, снимок плана или участок на карте → тип чертежа → граница → нормативные зоны и окружение → честное пятно застройки → участок в объёме → постройки с санитарными разрывами и земляными работами → лист СПОЗУ в DXF |
| **DWG-топосъёмка** | TIN-рельеф по отметкам и горизонталям, классификация объектов, полотно проездов, 2D-чертёж и 3D-сцена, экспорт DAE и DXF |
| **2D → 3D** | Реконструкция здания по чертежу: аудит листа, параметрический рецепт, решатель, независимая проверка; доступен при настроенном ключе модели |
| **Все объекты** | Архив результатов в браузере с превью и повторным открытием |

Четыре готовых участка в `public/demo/` читаются тем же парсером, что и файл
пользователя: показ — настоящая работа программы.

Перед расчётом определяется тип чертежа по именам слоёв: топосъёмка, генплан,
комплект здания, интерьер или узел. Посадка запускается только на первых двух —
разрез музея и лист фасадов участком не становятся. Решение и его основания
видны на экране, роль любого слоя можно поправить вручную.

## Запуск

```bash
npm install
npm run dev
```

Переменные окружения описаны в `.env.example`. Без ключей приложение работает
для геометрических расчётов, карт, топографии и экспорта. Ключ нужен для ИИ-реконструкции и дополнительных ИИ-проверок CAD.

Вход, регистрация и синхронизация проектов держатся на базе Cloudflare D1.
Локальная копия базы заводится сама: `npm run dev` перед запуском накатывает на
неё миграции из `migrations/`. Отдельно то же делает `npm run db:local`. Файл
базы лежит в `.wrangler/state` и в git не попадает.

Для Featherless можно задать `FEATHERLESS_API_KEY_2`: при временно занятой
модели запрос попробует запасной аккаунт. Ошибки доступа, оплаты и квоты
останавливают запрос; смена ключа на них не применяется. Всего не более пяти
попыток, с паузой после обхода доступных аккаунтов.

Если полный рецепт здания не помещается в ответ даже после увеличения лимита,
2D → 3D разбирает его по объёмам: общий план, затем параметры каждого объёма.
Единицы и центр здания общие; неполный рецепт не выдаётся за готовый результат.
Этот путь занимает больше запросов и времени. Проверка модели начинается
после сборки с полным бюджетом времени.

ИИ-проверки CAD запускаются вручную. Большие словари читаются последовательными
порциями; браузер получает этапы по NDJSON. API также сохраняет обычный JSON-ответ
для клиентов без заголовка `Accept: application/x-ndjson`.

Проверки:

```bash
npm run lint
npm run typecheck
npm test
npm run check:drawings -- fixtures/drawings
```

`npm test` собирает production-сборку и прогоняет модульные тесты: разбор DWG и
DXF, определитель типа чертежа, роли слоёв, TIN, геометрию, зоны сетей и
окружения, посадку, рельеф участка, постройки, лист, солнце, экспорт и рендер
страницы.

`check:drawings` прогоняет конвейер по папке настоящих чертежей и печатает
сводку: что открылось, что признано участком и почему.

## Развёртывание

Сборка `vinext` целится в Cloudflare Workers. Один раз авторизуйтесь и разверните:

```bash
npx wrangler login
npm run deploy
```

Ключи для режима 2D → 3D задаются как секреты Worker:

```bash
npx wrangler secret put FEATHERLESS_API_KEY
```

### База данных

Учётные записи и проекты живут в Cloudflare D1. База заводится один раз:

```bash
npx wrangler d1 create aedexa
```

Команда напечатает `database_id` — впишите его в `wrangler.jsonc` вместо
текущего. После этого схема накатывается на базу:

```bash
npm run db:remote
```

Порядок обязателен: сначала база и её идентификатор, потом `npm run deploy`.
Схема меняется только новым файлом в `migrations/` — правка уже применённого
файла на боевой базе не повторится.

Проверка после развёртывания: `curl https://адрес-сайта/api/auth` отвечает
`{"account":null}`. Ответ с `NO_DATABASE` означает, что привязка `DB` до
Worker не доехала, и вход работать не будет.

## Структура

```
app/
  api/            маршруты языковой модели: cad-groups, cad-semantics, reconstruct
  components/     AedexaApp (посадка), PlacementScene (участок в объёме),
                  CadProcessingView и CadViewport (топосъёмка), MapSourceView,
                  ReconstructionWorkspace, ArchiveWorkspace
  lib/
    placement/    посадка: тип чертежа, роли слоёв, движок отступов и пятна,
                  DXF, рельеф, постройки, окружение, лист, карта
    cad/          конвейер DWG: разбор, классификация, TIN, дороги, экспорт
    norms/        реестр норм с паспортом источника каждого правила
    ai/           общий клиент провайдеров модели
    geometry/     2D-примитивы
docs/             устройство и выкладка
public/demo/      готовые участки в DXF
tests/            автоматические проверки
```

## Ограничения

Нормативные значения — типовые и помечены как требующие проверки по действующей
редакции. Красная линия, кадастровая граница и охранные зоны требуют официальных
источников; распознавание снимка их не заменяет. Приложение не выпускает рабочую
документацию и не заменяет CAD- и BIM-системы.
